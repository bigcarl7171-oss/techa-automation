## 3. 3단을 유지하면서 중복을 없애는 방법

3단 자체는 문제가 아니다. 문제는 **세 칸이 같은 일을 하는 것**이다.
지금 카테고리 메뉴가 좌측 사이드바 + 우측 위젯 + 본문 그룹 제목, 세 곳에 있다.

### 각 칸에 하나의 일만 준다

| 칸 | 지금 하는 일 | 앞으로 할 일 |
|---|---|---|
| **좌측 사이드바** | 카테고리 7개 + 매거진 + 안내 (중복 1) | **카테고리 내비게이션 전담** + 개수 배지. 현재 위치 표시(`aria-current`). **도구 페이지에도 유지** |
| **본문** | 히어로·통계칩·매거진·도구목록·그룹제목 (중복 3) | **도구 찾기 전담**: 히어로+검색 → 인기 도구 → 전체 도구 |
| **우측** | 인사말(정보량 0) + 카테고리(중복 2) + 매거진 | **최근 쓴 도구** + 매거진. 카테고리 위젯 삭제 |

### ★ 좌측 사이드바를 도구 페이지까지 확장한다 (이번 리뉴얼의 핵심)

modan의 "다른 도구로 바꾸기 드롭다운"과 같은 목적을, 테차는 **이미 있는 3단 셸을
도구 페이지에도 쓰는 것**으로 달성한다. 3단 유지 지시와 완벽히 맞물린다.

- 도구 페이지도 `.shell` 구조를 쓴다 → 좌측에 카테고리 21개 내비가 **항상** 있다
- 홈으로 돌아가는 왕복이 사라진다. 계산 끝 → 왼쪽에서 다음 도구 클릭
- 데스크톱에서 3단이 처음으로 **정당한 이유**를 갖는다 (지금은 홈에서만 쓰이고 중복만 만든다)
- 모바일에서는 접힌 `<details>` 드롭다운으로 (modan 패턴 그대로)

```
현재                                 변경 후
홈: [카테고리|본문|위젯]              홈:      [카테고리|도구찾기|최근+매거진]
도구페이지: [    본문만    ]          도구페이지:[카테고리|  도구  |관련+매거진]
                                              ↑ 같은 사이드바가 계속 따라온다
```

### 우측 칸을 "최근 쓴 도구"로 바꾼다

인사말 위젯(`index.html:122-126`)을 삭제하고 그 자리에 **최근 사용한 도구 5개**를 넣는다.

- `localStorage`로 구현. 빌드 스텝 불필요, 서버 불필요, 개인정보 서버 전송 없음
- 재방문자에게 가장 가치 있는 정보 = 지난번에 쓴 그 도구
- **템플릿 필러로 오해받을 수 없는 기능** → AI 티 제거에 직접 기여
- 비어 있을 때는 인기 도구 5개를 보여준다 (§4.5 empty state)

```js
// site.js — 도구 페이지 진입 시 기록
function recordRecent(slug) {
  try {
    var k = "techa.recent";
    var list = JSON.parse(localStorage.getItem(k) || "[]")
      .filter(function (s) { return s !== slug; });
    list.unshift(slug);
    localStorage.setItem(k, JSON.stringify(list.slice(0, 5)));
  } catch (e) { /* 시크릿 모드 등에서 무시 */ }
}
```

## 4. 문구 (브랜드 2차, 도구 1차)

### 4.1 한 문구에 다 담기 — 추천안

계산기 + 재미 + 실용도구를 한 번에 함축하고, "서랍" 브랜드 은유와도 맞아야 한다.

| # | 문구 | 담긴 것 | 평가 |
|---|---|---|---|
| **A** | **계산도, 변환도, 심심풀이도.<br>필요할 때 꺼내 쓰는 도구 21개** | 계산기·실용(변환)·재미(심심풀이) + 서랍(꺼내 쓰는) + 개수 | **추천.** 셋을 병렬로 다 담고 "꺼내 쓰는"이 서랍 은유를 자연스럽게 살린다 |
| B | 만 나이부터 로또까지,<br>생활에 필요한 도구 21개 | 구체 명사 2개 + 개수 | 검색어(만 나이)를 첫 단어로. "로또까지"가 재미를 암시. A보다 검색 친화, 함축은 약함 |
| C | 계산기·변환기·심심풀이 21개,<br>서랍에서 바로 꺼내 쓰세요 | 셋 + 서랍 + 개수 | 명사 나열이 딱딱하다 |
| D | 자잘하지만 매번 필요한 것들.<br>계산기부터 심심풀이까지 21개 | 공감 + 셋 + 개수 | 첫 줄이 좋지만 기존 "자잘한 고민"과 겹쳐 재활용 느낌 |

**A안 채택 시 히어로 전체:**

```
계산도, 변환도, 심심풀이도.
필요할 때 꺼내 쓰는 도구 21개

[ 어떤 계산이 필요하세요?              🔍 ]

로그인도 설치도 없습니다. 입력한 값은 브라우저 안에서만 계산됩니다.
```

- 배지 `무료 온라인 도구` **삭제** — 아래 본문과 중복 (§4.7 hero stack, 텍스트 4개 이하)
- CTA 버튼 `도구 둘러보기 →` **삭제** → 검색창이 CTA 역할. 도구 허브의 첫 행동은
  "둘러보기"가 아니라 "찾기"다 (onul.works가 h1을 검색 프롬프트로 쓰는 것과 같은 판단)
- 개인정보 한 줄은 modan의 `✓ 저장 안 함` 패턴. 계산기 사이트에서 실질 신뢰 요소다

## 5. AI 티를 없애는 구체 항목

## 6. 클릭하고 돌아오는 흐름

사용자가 지적한 핵심. 현재 경로와 개선 경로를 나란히 둔다.

### 지금 (도구 2개를 쓰려면 6단계)

```
홈 → 스크롤로 도구 찾기 → 만 나이 계산기 → 계산
  → 뒤로가기(홈) → 다시 스크롤 → 글자수 세기 → 계산
```
- 도구 페이지에 검색창이 없다
- 좌측 카테고리 내비가 없다 (홈에만 있다)
- `관련 도구`는 같은 카테고리 3개뿐 → 카테고리를 넘어가면 무용
- breadcrumb의 카테고리 링크는 **깨져 있다** (§1-2). 눌러도 홈 맨 위로만 간다

### 개선 후 (3단계)

```
홈 → 검색 or 인기도구에서 만 나이 계산기 → 계산
  → 왼쪽 사이드바에서 글자수 세기 클릭 → 계산
```

| 조치 | 구현 | 효과 |
|---|---|---|
| 도구 페이지에 3단 셸 적용 | `.shell` 구조 재사용 | 좌측 카테고리 내비가 항상 있음 |
| 도구 페이지 상단에 검색창 | `.shell-topbar` 재사용 | 이름을 아는 도구로 직행 |
| breadcrumb 앵커 수정 | `site.js:96` 한 줄 | 카테고리로 실제 이동 |
| 모바일: 접힌 전체 도구 | `<details>` (modan 패턴) | JS 없이 21개 전부 접근 |
| 최근 쓴 도구 5개 | `localStorage` | 재방문 1클릭 |
| 관련 도구 3개 → 카테고리 전체 + 인기 3 | `renderRelated` 확장 | 카테고리를 넘는 이동 |
| 결과 복사 버튼 | 기존 `renderShare` 확장 | 계산 후 이탈 대신 행동 완결 |
| `aria-current="page"` | 사이드바 현재 항목 | 지금 어디인지 보임 |

## 8. 모바일 반응형 상세 검토

3단을 유지하면 모바일 설계가 더 중요해진다. 현재 두 개의 브레이크포인트가 있다.

### 8.1 현재 동작과 문제

**`@media (max-width: 1080px)`** (`landing.css:270-288`)

| 현재 | 문제 |
|---|---|
| `.shell-sidebar`가 가로 스크롤 행으로 변신 | 카테고리 7개 + 매거진 + 안내 3개가 **한 줄에 섞여** 가로 스크롤. 오른쪽에 뭐가 더 있는지 안 보인다 |
| `.shell-nav-label { display:none }` | "카테고리"·"테차"·"안내" 구분이 사라져 11개 링크가 무맥락 나열 |
| `.shell-right`가 최하단으로 | 도구 21개를 다 지나야 도달. **사실상 안 보인다** |
| `overflow-x: auto`에 스크롤 힌트 없음 | 더 있다는 신호가 없다 |

**`@media (max-width: 640px)`** (`landing.css:289-299`)

| 현재 | 문제 |
|---|---|
| `.shell-tool-desc { display:none }` | **도구가 뭔지 모른 채 이름만 보고 선택** |
| `.shell-tool-cat-tag { display:none }` | 이건 타당 (그룹 제목과 중복) |
| `.shell-cta-pill { display:none }` | 선물샵 진입점이 모바일에서 사라짐 (브랜드 2차이므로 수용 가능) |
| `.shell-topbar { flex-wrap: wrap }` | 검색창과 아이콘 2개가 2줄로 접힘 |
| 히어로 `h1` 24px | 타입 스케일 개정에 맞춰 28px |

### 8.2 개선안

**≤1080px (태블릿)**

- 사이드바 → **카테고리 칩만** 가로 스크롤 (매거진·안내는 푸터로 이동).
  한국 모바일 웹의 표준 패턴이고 modan도 캠페인 내비를 이렇게 쓴다
- 칩에 개수 배지 유지 → 스캔 가능
- 우측 칸을 **분해**: `최근 쓴 도구`는 도구 목록 **위로**, `매거진`은 아래로.
  재방문자에게 가장 중요한 것이 먼저 온다
- 가로 스크롤 우측에 페이드 마스크로 "더 있음" 암시
  (`mask-image: linear-gradient(90deg,#000 85%,transparent)`)

**≤640px (모바일)**

- **도구 설명 복원** — 2줄 클램프. 카테고리 태그·화살표만 숨긴다
- 검색창 전체폭 1줄, 아이콘 버튼 2개는 같은 줄 우측
- 히어로 패딩 `24px`, `h1` 28px
- 카테고리 칩 행을 **sticky** (`position:sticky; top:0`) → 21개 스크롤 중에도 이동 가능
- 터치 타깃: `.shell-tool-row`는 이모지 38px + 패딩 22px = 약 60px로 **충족**.
  단 `.shell-icon-btn`·`.shell-widget-btn`·푸터 링크는 실측 후 **최소 44px** 보정 (WCAG 2.5.5)
- `.shell-carousel` 가로 스크롤에 `scroll-snap-type: x mandatory` 추가

**≤380px (소형 단말)** — 현재 미대응

- `.shell-stat` 계열 잔여 요소 세로 전환
- 히어로 `h1` 24px로 한 단계 더
- 도구 이모지 38px → 34px, 이름 줄바꿈 여유 확보

### 8.3 모바일 확인 체크리스트

- [ ] 320 / 375 / 390 / 414 / 768 / 1024 / 1280px에서 가로 스크롤 없음
- [ ] 도구 설명이 모든 폭에서 보임
- [ ] 카테고리 칩이 sticky로 따라옴
- [ ] 최근 쓴 도구가 도구 목록보다 위
- [ ] 터치 타깃 44px 이상
- [ ] `word-break: keep-all` 적용 후 좁은 폭에서 어색한 끊김 없음
- [ ] iOS Safari 주소창 접힘 시 레이아웃 점프 없음 (`dvh` 사용 여부 확인)
- [ ] 실제 단말 확인 (에뮬레이터만으로 판단하지 않는다)

## 9. 인터랙션 (`emil-design-eng`)

**이 사이트는 이미 잘 하고 있다**: 커스텀 이징 변수(`--ease-out` `--ease-in-out`),
호버 게이팅(`@media (hover:hover) and (pointer:fine)`), 속성 지정 트랜지션.
`transition: all`·`ease-in` 사용 0건. 아래는 남은 빈칸만.

| Before | After | Why |
|---|---|---|
| `.shell-tool-row`에 `background-color` 트랜지션만 | `transform 140ms var(--ease-out)` 추가 + `:active{transform:scale(0.99)}` | 가장 많이 눌리는 요소에 press 피드백이 없다 |
| `:focus-visible` 0건 | `outline: 2px solid var(--blue-ink); outline-offset: 2px` | 키보드로 21개를 훑을 때 위치 불명 |
| `prefers-reduced-motion`이 `landing.css`에만 | `style.css`에도 추가 | 도구 페이지가 보호 밖 |
| `.reveal` 전역 지연 계단 | 첫 2개 그룹은 지연 0 | 첫 화면이 등장을 기다리게 하지 않는다 |
| 검색 입력 → 즉시 필터 | **유지, 애니메이션 넣지 않음** | 타이핑마다 반복. Emil: 고빈도 동작은 애니메이션 제거 |
| 도구 행 hover = 배경색만 | **유지, `translateY` 넣지 않음** | 21행이 세로로 붙어 있어 리프트가 목록을 들썩이게 한다 |
| 최근 쓴 도구 목록 갱신 | 트랜지션 없이 즉시 | 페이지 로드 시점 1회. 애니메이션 이유 없음 |

`.shell-tool-row`의 press는 `scale(0.99)`. 버튼용 `0.97`은 붙어 있는 행 사이 간격이 튄다.

**추가하지 않을 것**: 스크롤 하이재킹, 마키, 스티키 스택, 패럴랙스, 커서 물리, 무한 루프.
`MOTION_INTENSITY: 5`가 이 사이트의 적정값이고 올릴 이유가 없다.

## 9.5 진행 현황

**1일차·2일차 작업을 로컬에서 먼저 끝냈으나, 커밋 전 `git fetch`에서 원격에 14개의
새 커밋이 이미 올라와 있는 것을 발견했다.** 다른 세션이 같은 리포트를 근거로 상당 부분을
이미 처리했고, 사이트 전체 검색 기능 신규 추가 · 21개 도구 페이지 전체에 tactile
interaction 적용 · 계산기 로직 재작성 등 이 문서 범위 밖의 작업도 포함돼 있었다.

로컬 변경을 스태시해 원격을 먼저 pull하고, **이미 처리된 항목은 버리고 진짜 델타만
재적용**했다. 결과:

| 작업 | 실제 상태 | 비고 |

| owner 배너 제거 | **원격이 더 나은 해법으로 이미 처리** | 삭제 대신 기본 `hidden` + `?admin=1`일 때만 노출. 운영 체크리스트 링크 기능은 유지하면서 방문자에게는 안 보임 |
| breadcrumb 앵커 `/#` → `/#cat-` | 원격에 이미 반영 | |
| 광고 문구 주입 중단 | 원격에 이미 반영 (`display:none`으로 숨김) | |
| 대비 토큰 3종 + `--blue-ink` | 원격에 이미 반영, **동일한 값** | 같은 리포트 기반 작업이라 수치까지 일치 |
| `word-break: keep-all` | 원격에 이미 반영 | |
| 도구 행 `:active` + hover 게이팅 | 원격에 이미 반영 (`scale(0.98)`) | |
| 모바일 도구 설명 복원 | 원격에 이미 반영 | |
| 통계 칩 → 신뢰 문구 3줄 | 원격에 이미 반영, **문구까지 거의 동일** | "로그인 없이 바로" 등 |
| 인사말 위젯 삭제 | 원격에 이미 반영 | |
| 섹션 제목 정리 | 원격에 이미 반영 (개수는 JS로 동적 계산) | |
| **히어로 H1** | **델타로 재적용** | 원격은 B안 계열("만 나이, D-Day, 대출이자...")로 가 있었음. 사용자가 최종 승인한 A안("계산도, 변환도, 심심풀이도...")으로 교체 |
| **`:focus-visible`** | **델타로 재적용** | 원격 작업에 없었음 |
| **도구 페이지 `prefers-reduced-motion`** | **델타로 재적용** | `landing.css`에는 있었으나 도구 페이지가 로드하는 `style.css`에는 없었음 |
| 사이드바 라벨 이모지 제거 | **적용 안 함** | 원격의 최근 커밋("Apply tactile interaction + anti-slop rules site-wide")이 이모지를 유지한 채로 anti-slop 정리를 이미 마쳤음. 더 최근의 의도적 결정으로 보고 재론하지 않음 |
| 도구 이름 2건 정리 | **적용 안 함** | 로컬 전용 변경이었고 원격 재작성과 충돌 위험이 있어 이번 델타에서 보류 |

**교훈**: 이 저장소는 여러 세션이 동시에 작업할 수 있다는 걸 세션 시작 시점에는 몰랐다.
`git fetch`를 커밋 직전이 아니라 **작업 시작 시점에** 했다면 처음부터 델타만 만들 수
있었을 것. `project_techa_utils` 메모리의 "동시 작업 위험" 경고를 다음 세션에서는 먼저
확인할 것.

### 검증 방법에 대한 기록 — 헤드리스 스크린샷의 함정

모바일 확인 중 히어로 본문이 오른쪽에서 잘리는 것처럼 보였다. 원본(`git archive HEAD`)을
별도 포트로 띄워 비교했더니 원본도 같아서 기존 버그로 의심했으나, **페이지 안에서 직접
`getBoundingClientRect`로 측정하니 넘침이 전혀 없었다.**

- 320px 뷰포트: `documentElement.scrollWidth = 305` = 뷰포트 폭 → 가로 넘침 0
- `.shell-hero p`: `w=221, scrollW=221, h=46` → 2줄로 정상 줄바꿈, 클리핑 없음
- `.shell-main`: `w=305, scrollW=305` → 깨끗함

원인은 **헤드리스 Edge가 약 480px 미만 `--window-size`에서 레이아웃 폭을 클램프**하고
이미지만 요청 폭으로 잘라내는 것이었다. 480px·700px 스크린샷은 정상이었고 360·375·390px만
잘려 보였다.

**교훈**: 좁은 폭 검증은 스크린샷만 믿지 말고 페이지 안에서 실측하거나 실제 단말로 확인한다.
§8.3의 "실제 단말 확인" 항목이 형식적인 문구가 아니다.

## 11. 절대 건드리지 않을 것

`main`에 푸시하면 **즉시 techa.kr에 배포**되고, 과거에 실수로 사이트 파일을 지운 이력이 있다.

- URL·라우트 (`/ko/<slug>/` 21개)
- **앵커 id `#cat-*`** — 링크를 id에 맞추는 것이지 id를 바꾸는 게 아니다
- 폼 필드 id (`#p` `#r` `#y` 등) — GA4·자동완성 영향
- 로고·워드마크, 카테고리 이름, 법적 문구(`/privacy/` `/terms/`)
- `wrangler.toml`의 `name = "techa-automation"` — Cloudflare 프로젝트명. "고치면" 배포가 깨진다
- 브랜드 3색·서체 조합
- 매거진 글 링크를 JS 생성으로 되돌리지 않는다 (네이버 Yeti 크롤러 대응, `docs/blog-seo-guide.md`)

**배포 절차**: 2주차 전 백업 커밋 → 단계별 별도 커밋 → 푸시 전 `git fetch`
(다른 세션이 이 저장소에 직접 푸시한 이력 있음) → 파일 삭제 포함 커밋은 특히 확인.
