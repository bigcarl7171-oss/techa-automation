# 사이트 제작 원칙 & 인사이트 (외부 자료 교차검증)

> 출처: 네이버 AI의 유틸리티 사이트 수익화 답변을 기존 자사 문서
> (`viability-assessment` / `monetization-strategy` / `monetization-alternatives` / `top30-roadmap`)와 교차검증해 도출.
> 목적: 앞으로 만드는 모든 앱이 지켜야 할 방향을 한 곳에 고정.

---

## 1. 외부 자료가 우리 전략을 검증해 준 부분 (이미 반영 중 ✅)

네이버 AI 답변의 대부분은 우리가 이미 하고 있는 것과 일치 → 방향이 맞다는 외부 확인.

| 외부 자료 요점 | 우리 현황 |
|---|---|
| "핵심은 기능이 아니라 검색 유입·재방문 트래픽" | ✅ 생존성 평가·수익화 문서의 핵심 논지와 동일 |
| 기능 중심 키워드를 제목·설명에 | ✅ 20개 앱 전부 title/description에 핵심 키워드 |
| 모바일 최적화·빠른 실행 | ✅ 정적·client-side·반응형 |
| 재방문 요소(로또 주간·운세 일간) | ✅ 오늘의 운세(일간)·로또·메뉴룰렛 등 배치 |
| SEO 기초(Search Console·Analytics·sitemap) | ✅ sitemap/robots 완료, SC·GA는 진행 예정 |
| 제휴는 관련성 매칭(건강→운동·보험) | ✅ monetization-alternatives에 도구별 매칭 정리 |
| 광고를 방해적으로 두지 말 것 | ✅ 광고 슬롯을 도구 위/아래에만, 입력↔결과 사이엔 안 넣음 |

## 2. 새로 채택하는 인사이트 (기존 문서에 없던 것 🆕)

### 🆕 A. "공유·재방문"을 기능으로 내장한다
단순히 재방문형 주제를 고르는 데서 그치지 말고, **결과를 이미지 카드/링크로 공유하는 버튼**을 도구에 내장.
→ 광고비 0으로 SNS 외부 유입 확보. (특히 궁합·운세·테스트·로또 결과)
- **실행**: 결과 영역에 "결과 공유/이미지 저장" 버튼 추가(캔버스로 결과 카드 생성 → 다운로드/Web Share API).

### 🆕 B. 프리미엄 구조를 "초기 설계"에 반영한다
지금 유료화하지 않더라도, **나중에 잠글 지점을 미리 표시**해 두면 확장이 쉽다.
- 유료 후보 기능: 결과 저장, 다수 명단 관리(사다리·팀), **PDF 결과 다운로드**, 광고 제거, 대량 처리, 무제한.
- **실행**: 앱 설계 시 "이 기능은 향후 프리미엄" 주석을 남기고, 무료/유료 경계를 구조적으로 분리.

### 🆕 C. 광고 배치 규율을 원칙으로 고정
유틸리티는 체류가 짧다 → 광고가 사용 흐름을 끊으면 이탈·신뢰 하락.
- **원칙**: 광고는 ①도구 상단(첫 화면 위) ②결과 아래 ③본문 설명 중간에만. **입력과 결과 사이(상호작용 핵심 구간)엔 절대 금지.**

### 🆕 D. "서비스 매각(사이트 플리핑)"을 장기 exit 옵션으로 인지
반복 방문형 도구는 트래픽·수익이 안정되면 **사이트·도메인·운영권 매각**이 가능(Flippa 등).
- **함의**: 지금처럼 **깔끔한 표준 스택 + 문서화**를 유지하면 이전·매각이 쉬움(이미 잘하고 있음). 포트폴리오형으로 키우면 매각 가치↑.

### 🆕 E. 고반복 도구는 "앱화(PWA)"로 리텐션 강화
로또·운세·사다리처럼 자주 쓰는 도구는 **PWA(홈 화면 추가)**로 재방문·인앱 광고 여지 확보.
- **실행(향후)**: `manifest.json` + 서비스워커 추가 → "홈 화면에 추가" 가능. 플랫폼 정책(앱스토어)보다 부담 적음.

## 3. 앞으로 모든 앱에 적용할 체크리스트 (갱신판)

기존 규격(1앱=1URL, 설명 300자+, 내부링크, JSON-LD)에 아래를 추가:

- [ ] 기능 중심 키워드를 title·h1·description에 (검색어 그대로)
- [ ] 재방문/공유 요소 여부 판단 → 있으면 **공유 버튼** 내장
- [ ] 광고 슬롯은 상단·결과 아래·본문 중간에만 (입력↔결과 사이 금지)
- [ ] 향후 프리미엄이 될 기능은 주석으로 경계 표시
- [ ] 모바일에서 한 손 조작·빠른 실행 확인
- [ ] 제휴/자사상품 연결 지점이 있으면 CTA 슬롯 배치(예: 건강→운동용품, 감성→TECHA 선물)

## 4. 수익 모델 로드맵 (확장 반영)

| 단계 | 모델 | 비고 |
|---|---|---|
| 지금 | 제휴 + TECHA 자사 상품 CTA | 승인·도메인 불필요 |
| 트래픽 형성 | 애드센스/Ezoic (배치 규율 준수) | 도메인 연결 후 |
| 성장 | Mediavine/Raptive + 금융 리드 | RPM 2~4배 |
| 성숙 | **프리미엄 기능(저장·PDF·광고제거)** + 직접 스폰서 | B안 설계 활용 |
| 고반복 도구 | **PWA 앱화 + 인앱 광고** | E안 |
| 장기 exit | **사이트 매각(플리핑)** | D안, 포트폴리오화 시 |

## 5. 2차 교차검증 (Gemini 심층 분석) — 우리가 실제 보완할 갭

Gemini 분석도 큰 그림(트래픽·재방문 핵심, thin content 거절, 하이브리드 구조, RPM 언어·카테고리 격차)은 우리와 일치. 단, **구체적 실행 기준에서 우리가 아직 못 채운 갭 3가지**를 드러냈다.

### 🔧 갭 1 — 설명 콘텐츠 분량 상향: 300자+ → 800~1,500자 (품질 기준)
- 우리 현재 앱 설명글은 약 300~500자. Gemini는 애드센스 승인·YMYL 대응을 위해 **1,000~1,500자 이상**의 완성도 있는 정보성 글을 권장.
- ⚠️ 단, 생존성 평가의 교훈("2,000자 일반론도 저품질 판정")과 종합하면 **길이가 목적이 아니라 '진짜 유용한 깊이'가 목적**. 패딩 금지, 공식·기준표·FAQ·주의사항으로 자연스럽게 800~1,500자를 채운다.
- **실행**: 승인 신청 전, 주력 앱(금융·건강)부터 FAQ·기준표·공식해설을 보강해 분량·깊이 확대.

### 🔧 갭 2 — 필수 법적/안내 페이지 미비
- 현재 개인정보처리방침만 있음. Gemini·애드센스 정책이 요구하는 **이용약관·사이트 소개(About)·문의하기(Contact)**가 없음.
- **실행**: `/terms/`, `/about/`, `/contact/` 3개 페이지 추가 + 푸터 링크 연결. (승인 전 필수)

### 🔧 갭 3 — 크롤러가 JS 없이 핵심 텍스트를 보게
- 우리 설명 아티클은 정적 HTML이라 OK. 단 **`<h1>` 제목이 site.js로 JS 주입**됨 → 크롤러 안전성 위해 핵심 텍스트(h1)는 정적 HTML 권장.
- **실행**: 각 앱 `<h1>`을 정적으로 두거나, 최소한 title·description·아티클은 지금처럼 정적 유지(현재 충족).

### ✅ Gemini가 재확인해 준 것(이미 반영)
- 정적 HTML(SSG류)로 크롤러에 완성 문맥 제공 → 우리 순수 정적 구조가 이미 충족
- 광고를 결과 주변·아티클 중간에 자연스럽게(팝업·오버레이 금지) → build-principles 3-C와 동일
- 카테고리 전략: 금융 고CPC / 건강 에버그린·YMYL / 개발·텍스트 고재방문 / 엔터 바이럴+쿠팡 → top30-roadmap과 일치
- RPM 격차: 한국 엔터 $0.5~2, 한국 고단가 $5~15, 글로벌 영문 $15~40 → 우리 수치와 일치(i18n 영어확장 근거 강화)

### 📌 도출된 우선 실행 순서(승인 전 마감)
1. 필수 페이지 3종(이용약관·소개·문의) 추가 — **갭 2**
2. 주력 앱 설명글 800~1,500자로 깊이 보강 — **갭 1**
3. (선택) h1 정적화 — **갭 3**
→ 그 후 Search Console 등록 → 애드센스 신청

## 한 줄 요약
외부 자료 2건(네이버·Gemini)은 우리 방향(**트래픽·재방문이 핵심**)을 재확인해 줬고,
채택할 신규 원칙은 **①공유 버튼 내장 ②프리미엄 경계 사전 설계 ③광고 배치 규율 ④매각 exit ⑤PWA 앱화**,
그리고 **승인 전 반드시 닫아야 할 갭 3가지 = 법적 페이지 3종 · 설명글 깊이(800~1,500자) · h1 정적화**다.
