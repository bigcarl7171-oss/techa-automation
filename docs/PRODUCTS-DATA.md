# 테차 상품 데이터 (techa-products.json)

테차 전 상품의 **단일 소스**. 카드뉴스·쇼츠·블로그 초안·사이트 도구가 전부 이 파일 하나를 본다.

- **데이터**: `assets/data/techa-products.json`
- **생성 스크립트**: `scripts/build-products.py`
- **가격 원본**: `docs/테차상품가격리스트.xlsx` (2026-08-04 레포 안으로 이동 — 어느 컴퓨터에서
  clone해도 그대로 재생성 가능. `.assetsignore`에 `/docs`가 있어 사이트로는 서빙 안 됨)

---

## 구조

147개 SKU를 **25개 제품 라인**으로 묶고, 추천 태그는 **라인 단위**로 관리한다.
색상·사이즈·단수·전원방식 같은 변형은 라인 아래 `variants`에 담긴다.

> 왜 라인 단위인가: `파랑장미수국 미니`와 `보라장미수국 라지`의 추천용도가 다를 이유가 없다.
> SKU마다 태그를 달면 147번 입력해야 하고 반드시 어긋난다. 라인에 달면 25번이면 되고
> 일관성 문제가 사라진다.

```json
{
  "id": "money-cake",
  "name": "용돈케이크 머니박스",
  "category": "용돈박스",
  "material": "비누꽃+케이크모형+LED등+투명박스",
  "priceMin": 29800, "priceMax": 49800,
  "priceBands": ["3만원대", "5만원 이상"],
  "recipient": ["부모님", "조부모님"],
  "occasion": ["생신·환갑", "칠순·팔순", "어버이날"],
  "giftType": ["현금동봉형"],
  "situation": "현금만 드리기엔 민망하고 거창한 이벤트는 부담스러울 때",
  "reason": "케이크 모양에 현금을 꽂고 LED 조명까지 들어가, 촛불 대신 불을 켜고…",
  "url": null,
  "skuCount": 6,
  "variants": [
    { "sku": "용돈케이크 라벤더퍼플 머니박스 1단 중대형",
      "price": 29800, "color": "라벤더퍼플", "tier": "1단", "size": "중대형" }
  ]
}
```

`situation` / `reason`은 같은 폴더의 `menu-items.json`과 같은 패턴이다 — 추천 엔진에
그대로 물릴 수 있고, 콘텐츠 초안 쓸 때 문장을 그대로 가져다 쓸 수 있다.

## 4개 축

| 축 | 값 |
|---|---|
| `recipient` (9) | 연인 · 배우자 · 친구 · 부모님 · 직장동료 · 조부모님 · 선생님 · 아이 · 본인 |
| `occasion` (21) | 기념일 · 프러포즈 · 생일 · 화이트데이 · 발렌타인데이 · 크리스마스 · 집들이·개업 · 승진·퇴임 · 어버이날 · 스승의날 · 생신·환갑 · 칠순·팔순 · 소소한 감사 · 단체·답례품 · 빼빼로데이 · 병문안 · 발표회·재롱잔치 · 졸업·입학 · 설날·명절 · 데이트 · 취미·자기계발 |
| `giftType` (7) | 휴대전달형 · 현금동봉형 · 단체·답례품 · 아이용 · 인테리어형 · 함께보내기 · 체험형 |
| `priceBand` (5) | 1만원대 · 2만원대 · 3만원대 · 4만원대 · 5만원 이상 (가격에서 자동 계산 — 손으로 넣지 않는다) |

한 라인이 여러 값을 가질 수 있다(배열). 그래서 "5만원 이하 + 부모님 + 현금동봉형" 같은
조합 조회가 된다 — 이게 추천용도를 한 칸에 쉼표로 몰아넣지 않은 이유다.

## 쓰는 법

```python
import json
d = json.load(open('assets/data/techa-products.json', encoding='utf-8'))

# 부모님 + 5만원 이하
[l for l in d['lines'] if '부모님' in l['recipient'] and l['priceMin'] <= 50000]

# 아이 발표회 선물
[l for l in d['lines'] if '발표회·재롱잔치' in l['occasion']]
```

| 어디서 | 어떻게 |
|---|---|
| 카드뉴스 | "5만원 이하 부모님 선물 5가지" 같은 나열형 원고를 데이터에서 바로 뽑음 |
| 쇼츠 | `techa-video-factory` 스킬의 상품 선택 단계에서 참조 |
| 블로그 | 시즌 글에 가격대별 실제 상품·가격 삽입 |
| 사이트 | 선물 추천기 도구 (미구현 — `menu-items.json` 추천 엔진 재사용 예정) |

## 갱신

가격이나 상품이 바뀌면 **xlsx를 고치고 스크립트를 다시 돌린다**:

```bash
python scripts/build-products.py
```

추천 태그(recipient/occasion/giftType/situation/reason)를 고칠 때는
`scripts/build-products.py` 안의 `LINES` 정의를 고친다. **JSON을 직접 편집하지 말 것** —
다음 실행 때 덮어써진다.

## 스마트스토어 링크 (2026-08-04 반영)

xlsx에 **5번째 열 "사이트링크"**가 추가됐고, 스크립트가 그 열을 직접 읽는다 — 별도로
어딘가에 다시 입력할 필요 없음.

- **라인 안 아무 SKU 행 하나에만 링크를 넣으면 된다.** 색상·사이즈는 같은 스마트스토어
  페이지의 옵션이라 라인 전체에 그 하나의 링크가 적용된다 (147개 SKU 전부가 아니라
  25개 라인당 1개).
- 카네이션 돈꽃다발과 장미 돈꽃다발처럼 **서로 다른 두 라인이 실제로는 같은 판매 페이지**를
  쓰는 경우도 있다(꽃종류를 그 페이지 안에서 옵션으로 고르는 구조) — 이런 경우 두 xlsx 행에
  같은 URL을 넣으면 된다. 정상적인 경우이니 걱정할 필요 없음.
- URL 형식이 `http`로 시작하지 않으면(오타 등) 자동으로 무시되고 스크립트 실행 시 경고로
  뜬다. 아직 링크 없는 라인도 실행할 때마다 목록으로 보여준다.
- xlsx에 아예 없는 라인(플라워클래스 등 `EXTRA_LINES`)은 스크립트 상단의 `URL_MAP`에
  수동으로 넣는다 — xlsx 쪽 값이 있으면 항상 그게 우선한다.

URL은 직접 채워야 한다 — 실제 판매 링크를 지어낼 수 없어 자동 생성하지 않는다.

## 주의

- **플라워클래스는 xlsx에 없다.** `script-guide.md` 3-8을 근거로 스크립트의 `EXTRA_LINES`에
  수동 추가했다(45,000~50,000원). xlsx에 정식으로 넣게 되면 `EXTRA_LINES`에서 빼야 한다.
- **`script-guide.md` 3장에도 상품 카탈로그가 있다.** 내용이 일부 다르다(가격 없음, 일부
  상품 누락). 상품 사실관계는 **이 JSON을 기준**으로 하고, script-guide는 리뷰 언어·소구점
  참고용으로만 쓴다.
- 이 파일은 사이트에 배포되는 경로(`assets/data/`)에 있어 **공개적으로 서빙된다.** 담긴
  가격은 스마트스토어에 이미 공개된 판매가라 새로 노출되는 정보는 없지만, 원가·마진 같은
  비공개 정보는 절대 이 파일에 넣지 말 것.
- **occasion 값은 감으로 늘리지 않는다.** 2026-08-04에 21개로 확장할 때 경쟁사(다음플라워)의
  실제 "상황별" 필터 24개를 조사해서 빠진 걸 채웠다(병문안·화이트데이·발렌타인데이·
  빼빼로데이·크리스마스). 값을 더 늘릴 땐 실제 사례 근거 없이 임의로 추가하지 말 것.
- **병문안 태그는 소재로 거른다 — 비누꽃 제외, 순수 프리저브드만.** 물·흙이 없어야 병실에
  부담이 없다는 논리라, `material`에 "비누"가 섞인 라인(비누꽃다발류, 비누꽃 낱개 박스)은
  대상에서 뺀다. 붙어있는 라인: 장미수국 꽃다발·수국 꽃다발·수페리어 장미(순수 프리저브드
  꽃다발) + 유리돔무드등·컵무드등(프리저브드+무드등) + 꽃엽서카드.
- **관계 친밀도(썸 vs 오래된 연인 등)는 이 JSON의 축이 아니다.** 상품 자체가 갈리는 게
  아니라 카피 톤만 달라지는 문제라서, `techa-shorts/script-guide.md` 3-5에 톤 가이드로
  분리해뒀다.
